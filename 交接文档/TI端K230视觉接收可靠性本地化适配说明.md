# TI端K230视觉接收可靠性本地化适配说明

> 适用范围：BalanceBall统一基础层。Task2～Task5以及独立滚球调试均复用本层，不在各任务中重复实现UART、跳变和速度保护。

## 1. 对旧建议的本地化结论

| K230组旧建议 | 当前处理 |
|---|---|
| 视觉UART删除中断/轮询双生产者 | 接受。正式接收只允许UART RX ISR写软件环形缓冲。 |
| 视觉UART启用FIFO | 接受。SysConfig和运行时初始化同时保证RX FIFO启用，阈值为1字节。 |
| 增加硬件错误统计 | 接受。分别统计overrun、framing、parity和break。 |
| 跳变门限60 mm改为150 mm | 接受。协议位置范围仍保持±150 mm。 |
| 两帧跳变候选确认 | 接受。确认成功后重建位置基准并把本次控制速度置0。 |
| 无效状态恢复时重建速度 | 接受。恢复首帧速度置0，不继承失效前控制速度。 |
| TI重新差分位置计算速度 | 不采用。当前正式串级闭环使用K230提供的`v`。 |
| 修改TI差分速度滤波和换向滤波 | 不采用。TI不再运行第二套差分测速器。 |
| `state`字符串语义校验 | 按此前裁决不做。只做字符格式检查，不解释TRACK/HOLD等字符串。 |
| `valid/measured`组合检查 | 接受。两者必须同为0或同为1，错误组合计数并拒绝进入观察层。 |
| 扩展完整闭环遥测 | 不做。保持16通道JustFloat，只在已有文本诊断中增加接收可靠性计数。 |
| 换行到达时间戳 | P1延期。先验收FIFO和单生产者；只有仍有明显积压才实现。 |

## 2. 最终UART结构

接线保持：

```text
K230 TX  → MSPM0 PB3 / UART3_RX
K230 GND → MSPM0 GND

MSPM0 PA21 / UART2_TX → 调参USB-TTL RX
MSPM0 PA22 / UART2_RX ← 调参USB-TTL TX
GND共地
```

PB3只能接K230 TX，禁止再接USB-TTL TX。

软件数据流：

```text
UART3 RX FIFO
→ UART3 ISR一次排空FIFO
→ VisionReceiver软件环形缓冲
→ 主循环VisionReceiver_Process()
→ ASCII组帧、CRC、字段、序号检查
→ VisionBallPositionObservation
→ BalanceBallControl统一串级闭环
```

主循环不再读取UART3接收寄存器，因此环形缓冲严格保持单生产者、单消费者。

## 3. 接收检查顺序

```text
ASCII边界与长度
→ CRC
→ 字段格式
→ valid/measured数值组合
→ K230 session和seq
→ pos协议范围±150 mm
→ measured帧速度绝对范围≤3000 mm/s
→ BalanceBall跳变/恢复检查
→ 控制速度限幅±1500 mm/s
```

`state`只保存，不参与上述判定。

无效帧中的`pos`原样保存供日志查看，但只有`valid=1 && measured=1`才允许刷新真实测量时间和控制位置。

## 4. 跳变与恢复

参数：

```text
正常单帧最大跳变：150 mm
候选确认：2帧
候选位置容差：20 mm
候选超时：200 ms
```

处理：

1. 与最后基准差不超过150 mm：正常接收。
2. 第一次超过150 mm：保存候选，不用于控制。
3. 下一帧与候选差不超过20 mm且未超时：确认新轨迹。
4. 确认后更新位置基准、控制速度置0并恢复控制。
5. 下一帧不一致或超时：用当前帧替换候选重新确认。

因此保留异常坐标保护，同时不会形成永久`POS_JUMP`锁拒。

收到`valid=0`、`measured=0`或失联后，保留最后控制位置作短时HOLD；重新获得真实测量时首帧速度强制为0。如果恢复位置与旧位置相差超过150 mm，仍需通过两帧候选确认。

## 5. 速度保护

当前速度来源只有K230 `v`：

```text
|v| > 3000 mm/s：认为协议测量不可信，整帧拒绝
1500 < |v| ≤ 3000 mm/s：位置仍可接收，控制使用±1500 mm/s限幅
恢复首帧、session变化和跳变REBASE：控制速度=0
正常帧：直接使用K230 v，不做TI差分滤波
```

这样既不会改变K230协议，也不会把异常速度静默伪装成0，同时能够限制速度环对摆杆产生的瞬时冲击。

## 6. 可检查计数

UART层：

```text
rx_byte_count
uart_overrun_count
uart_framing_error_count
uart_parity_error_count
uart_break_error_count
ring_overflow_count
```

协议层：

```text
parsed_frame_count
accepted_frame_count
crc_error_count
length_error_count
field_error_count
semantic_error_count（只统计valid/measured错误组合）
duplicate_count
old_sequence_count
resync_count
```

控制层：

```text
accepted_measurement_count
rejected_jump_count
jump_candidate_count
rebase_count
held_invalid_count
speed_clamp_count
last_measurement_time_ms
```

这些计数通过独立调参UART的现有`DBG,RX`和`DBG,FILTER`文本快照输出，不扩展JustFloat通道。

## 7. 首轮验收

1. K230连续发送至少1分钟，CRC、长度、字段、硬件overrun和ring overflow应保持0或不持续增长。
2. 拔掉再接回K230 TX，TI允许进入HOLD/LOST；恢复后首帧不产生大幅摆杆冲击。
3. 人为让位置跨越超过150 mm，第一帧不控制；连续两帧稳定在新位置后自动REBASE，不永久锁拒。
4. 发送`valid=0, measured=0`时控制位置不被无效帧覆盖，但日志仍保留K230帧中的原始`pos`。
5. 发送错误`valid/measured`组合时`semantic_error_count`增长，控制真实测量时间不刷新。
6. 所有正式滚球任务均使用同一套接收、跳变和速度保护，不允许任务代码自行绕过。
