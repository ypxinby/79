## 1. 先给结论

接下来的开发以代码实现为主，但不能把它理解为“只要生成代码就能完成”。整体设计已经足够支撑第一版完赛，后续不需要重新设计协议或推翻底层；真正的不确定性集中在三项实机问题：

```text
K230在摆杆倾斜和小车振动时的毫米坐标精度
步进电机、编码器和机械传动的实际响应速度
钢球摩擦、惯性和车辆转弯扰动下的PD参数
```

因此后续工作应理解为：

```text
约一半是代码和状态机落地
约一半是分阶段实机验收和参数确定
```

当前方案已经把模块边界、通信格式、任务目标、安全链和异常方向考虑得比较完整。只要严格按本清单逐步验收，调试过程应明显比同时开发所有功能顺利；但在静止中心平衡和题3通过前，不能提前承诺题4～6一次调通。

# 阶段4：完成题3，O→+50 mm→-50 mm

## 4.1 状态流程

```text
START
→ START_VERIFY
→ target=+50 mm
→ BALL_STAGE_POSITIVE
→ 真实pos进入+50±10 mm
→ target=-50 mm
→ BALL_STAGE_NEGATIVE
→ 真实pos进入-50±10 mm且稳定
→ DONE，停止计时但继续保持-50 mm
→ 等待人工正常STOP
```

## 4.2 到达判定

正端折返至少要求：

```text
新seq
valid=1
measured=1
abs(pos-50) <= 10 mm
```

第一版不要求在+50 mm长时间静止，否则可能无法满足5秒；但不得用`pred`提前折返。

最终-50 mm完成要求：

```text
新真实测量
abs(pos+50) <= 10 mm
abs(velocity_local)低于门限
连续保持约200～300 ms
```

具体速度门限通过实机曲线确定。

## 4.3 计时和超时

- [ ] 按键START立即开始题目计时。
- [ ] 启动三帧确认计入5秒。
- [ ] 目标是在约4～4.5秒内完成，保留余量。
- [ ] 超过5秒置`overtime=1`，继续安全控制，不突然停机。
- [ ] 超过更长安全上限仍未完成则FAULT或等待人工停止。

## 4.4 验收

- [ ] 从O点启动。
- [ ] 真实到达+50±10 mm。
- [ ] 自动折返。
- [ ] 最终稳定在-50±10 mm。
- [ ] 总时间≤5秒。
- [ ] DONE后继续保持-50 mm。
- [ ] 人工STOP后安全退出。
- [ ] 连续重复至少5次，成功率满足比赛需要。

## 4.5 题3失败时的优化顺序

```text
先调KP/KD/MAX/SLEW
再调整正负方向不同的控制限制
再考虑目标附近速度门限和稳定时间
再考虑简单分段目标速度
最后才考虑K230预测pred或复杂动力学
```

- [ ] 再次检测A线必须连续满足若干20 ms周期。
- [ ] 完成后立即锁存，不允许同一横线重复计圈。
- [ ] 起点附近左右抖动不能被判定为一圈完成。

时间、距离和连续周期全部做成配置参数，初值实车确定。

## 7.4 现有代码补齐

- [ ] 实现`FOLLOW_END_START_LINE_DETECTED`或新的H任务计圈接口。
- [ ] 实现`FOLLOW_END_LAP_COUNT`，或明确由`h_task_controller`管理。
- [ ] 激活并正确维护`current_lap`和`lap_cooldown_ms`，或删除无效旧逻辑避免误导。
- [ ] 计圈完成只上报事件，不直接关闭滚球控制。

## 7.5 验收

- [ ] 在A线上静止不会误报完成。
- [ ] 离开A后短时间重新压线不会误报完整一圈。
- [ ] 完整行驶一圈再次过A只触发一次。
- [ ] 连续跑两圈可正确得到两个独立事件（调试模式）。
- [ ] 正式题5/6第一圈事件锁存为DONE。

# 阶段8：完成题5，中心位置保持一圈

## 8.1 流程

```text
START
→ 三帧确认O点
→ target=0 mm
→ 小车平滑启动循迹
→ 离开A并使能终点检测
→ 直线和弯道持续保持O点
→ 再次通过A
→ 停止计时、锁存DONE
→ 继续循迹和保持O点
→ 等待人工STOP
```

## 8.2 第一版速度策略

```text
直线和弯道先采用同一稳定速度
球偏差增大时降低到LOW
视觉长时间丢失或轴故障时平滑停车
```

第一版不必先识别直线/弯道阶段，也不必实现弯道前馈。只要较低稳定速度能在30秒内完成一圈，就优先采用简单方案。

## 8.3 验收

- [ ] 正确离开A并使能计圈。
- [ ] 再次通过A只完成一次。
- [ ] 整圈时间≤30秒，建议控制在25～27秒内留余量。
- [ ] 全程目标始终为0 mm。
- [ ] 球误差绝对值尽量≤10 mm。
- [ ] 弯道中没有连续LOST或猛烈摆动。
- [ ] DONE后继续循迹和保持O点。
- [ ] 人工STOP能够平滑停车。
- [ ] 连续完整运行至少5次并记录成功率和最大误差。

## 8.4 若弯道失败

按顺序处理：

```text
降低整圈速度
降低进入弯道时的轮速变化
检查循迹左右轮修正是否过于猛烈
检查相机振动和倾斜坐标误差
增加滚球LOW速度监督
最后才增加弯道经验前馈
```

# 阶段9：完成题6，任意位置保持一圈

## 9.1 目标锁定流程

```text
START
→ 记录启动时seq
→ 只接受启动后的新真实帧
→ 连续3帧位置稳定
→ target_lock = median(pos1, pos2, pos3)
→ 永久冻结target_lock
→ 清除旧速度历史
→ target=target_lock
→ 启动小车循迹
```

## 9.2 锁定条件

- [ ] 三个不同新seq。
- [ ] `valid=1 && measured=1`。
- [ ] 三帧均位于合法水管范围。
- [ ] 三帧最大值与最小值差小于稳定门限。
- [ ] 本地速度接近静止。
- [ ] 在最大等待时间内完成。

## 9.3 永久冻结规则

以下事件均不得修改`target_lock`：

```text
小球偏离
单帧丢失
HOLD
LOST
重新识别
进入弯道
车辆减速
再次通过A
```

只有：

```text
人工RESET
开始新一轮题6
```

才能清除目标。

## 9.4 验收位置

至少测试：

```text
0 mm
+50 mm
-50 mm
正侧较远位置
负侧较远位置
```

## 9.5 验收

- [ ] 启动锁定值接近实际指定位置。
- [ ] 锁定后目标不漂移。
- [ ] LOST恢复后仍保持原目标。
- [ ] 整圈时间≤30秒。
- [ ] 全程相对`target_lock`误差尽量≤10 mm。
- [ ] 再次通过A后锁存DONE并继续运行。
- [ ] 人工STOP后清晰显示本轮目标、时间和最大误差。

# 阶段10：补齐联合异常处理

## 10.1 视觉异常

统一策略：

```text
<150 ms：保持最后真实位置和当前车速级别
150～400 ms：冻结阶段切换，车辆转LOW，摆杆受限回安全范围
>400 ms：进入VISION_HOLD，车辆平滑停车
连续3帧真实TRACK：允许自动恢复一次
持续丢失超过约2 s：FAULT，等待人工处理
```

具体时间可以调整，但必须有明确上限。

## 10.2 步进轴故障

包括：

```text
NOENC
FOLLOW
DIR
TIME
LIMIT
```

处理：

- [ ] 锁存滚球故障。
- [ ] 停止继续增大摆杆命令。
- [ ] 第3问终止本轮。
- [ ] 第4～6问车辆平滑停车。
- [ ] 禁止自动重新启用步进动作。
- [ ] 必须人工清故障和重新启动任务。

## 10.3 循迹丢线

- [ ] 继续复用现有有界丢线恢复。
- [ ] 丢线恢复期间滚球控制继续运行。
- [ ] 车辆转向命令不得绕过速度斜坡和输出限制。
- [ ] 恢复超时后平滑停车并FAULT。
- [ ] 不因滚球状态单帧变化改变左右转向方向。

## 10.4 UART异常

- [ ] 校验错误只丢帧，不影响上一次真实测量的短时保持。
- [ ] 重复或旧seq不重复更新D项。
- [ ] K230重启时清除视觉速度历史并重新三帧确认。
- [ ] 环形缓冲区溢出计数必须可在OLED或日志查看。

## 10.5 人工控制

区分：

```text
正常STOP：车辆平滑减速，滚球继续控制至车辆停止
ABORT：终止当前任务，记录原因，安全退出
ESTOP：立即停止底盘和步进输出
RESET：清除允许清除的故障并回到IDLE，不自动重启动作
```

## 10.6 验收

- [ ] 遮挡100 ms不会导致车辆突然停车。
- [ ] 遮挡超过400 ms车辆能够平滑停下。
- [ ] 放回球后按策略恢复或保持FAULT，不会永久逻辑卡死。
- [ ] 拔掉K230串口不会继续使用旧坐标无限控制。
- [ ] 步进堵转后车辆不会继续高速行驶。
- [ ] 循迹丢线恢复超时后不会无限原地转动。
- [ ] 急停始终优先于任务状态机。

# 16. 最终判断

当前设计内容对于第一版完整备赛TI模块已经比较完备，不需要继续长时间停留在架构讨论。下一步应开始按阶段1～4实施代码，并尽快用题3形成第一个完整闭环任务。

但应保持以下判断：

```text
代码状态机大概率可以顺利落地；
±1 cm和规定时间能否满足，必须由实机曲线证明；
如果静止中心和题3顺利通过，题4～6主要是并行调度、计圈和车速控制；
如果静止中心仍不稳定，继续生成更多题目代码不会提高完赛概率。
```

因此最关键的近期里程碑不是“一次生成全部题3～6代码”，而是：

```text
真实测量语义通过
→ 静止中心±10 mm通过
→ 题3在5秒内稳定完成
```

完成这三个里程碑后，整个子项目就进入相对可控的工程集成阶段。
