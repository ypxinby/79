# TI端H题滚球串级闭环最终实施方案

> 状态：2026-08-01审核冻结版。本文档覆盖此前草稿中与本次裁决冲突的内容；旧文档仅保留为设计背景。

## 1. 本轮目标

第一优先级完成并实装以下比赛控制链：

```text
K230真实pos、v
→ TI位置环生成目标钢球速度
→ TI速度环生成摆杆编码器目标count
→ 现有步进电机编码器位置内环
→ STEP/DIR执行与堵转、断线、方向、软件限位保护
```

本轮不增加积分环，不重写已经验证的编码器位置内环，不依赖`pred`完成控制或任务判定。

## 2. 已冻结的取舍

以下六项为最终裁决，后续实现不得自行恢复复杂方案：

1. K230帧中的`state`继续作为透传字符串保存，不做语义校验；TI只检查协议、序号、新鲜度、`valid`、`measured`、位置和速度数值范围。
2. 不建立“电机已经换向”“钢球已经换向”等语义状态。摆杆命令由连续串级公式自然换向，Task2只保留正目标、负目标和完成阶段。
3. 视觉异常保护维持当前实现：坏帧不覆盖最后有效帧，短时保持最后有效控制，超时进入LOST并回水平，恢复后重新进行真实帧确认。
4. 正常停止维持当前实现。只有Task1按横线条件自动停车；Task3～Task5中涉及底盘的任务持续循迹并等待人工停止。
5. 暂不实现车辆启动、加减速或弯道前馈。当前首先完成视觉串级闭环和编码器摆杆执行闭环。
6. 不扩展JustFloat遥测字段，不为了调试重构完整遥测语义。保留现有16通道和已有文本诊断即可。

同时冻结以下边界：

- 真实水管长度为250 mm。
- 协议位置保护范围为±150 mm。
- 比赛中心目标严格为0 mm；机械水平误差使用独立`BIAS`编码器count修正，禁止再用`T=-5`冒充中心。
- K230的`v`是速度环的正式反馈；TI位置差分速度不再参与正常控制。
- 到达、折返、最终稳定和Task6目标锁定只使用真实`pos`与真实`v`，禁止使用`pred`。

## 3. 串级闭环

### 3.1 位置环

```text
position_error_mm = target_mm - pos_mm
target_velocity_mm_s = KPOS × position_error_mm
target_velocity_mm_s限幅到±VMAX
```

为兼容已有串口工具，命令名继续使用`KP`，但其新语义是`KPOS`，单位为`(mm/s)/mm`。

### 3.2 动态提前制动

当钢球正朝目标运动时计算：

```text
stop_distance_mm = |v| × TD / 1000
                 + v² / (2 × brake_acceleration)
                 + BM
```

正向速度使用`AP`，负向速度使用`AN`。当剩余距离不大于预计制动距离时，将目标速度收窄到`VAPP`。速度环此时会自然生成反向摆杆命令，无需建立换向语义状态。

`+4.x cm/-4.x cm`只能是实测中可能出现的制动位置，不能写死为任务目标或固定换向点。

### 3.3 速度环与摆杆目标

```text
velocity_error_mm_s = target_velocity_mm_s - v_k230_mm_s
control_count = BIAS + KVEL × velocity_error_mm_s
requested_count = DIR × control_count
```

为兼容已有串口工具，命令名继续使用`KD`，但其新语义是`KVEL`，单位为`count/(mm/s)`，不再表示位置微分系数。

随后依次经过：

```text
MAX控制权限限幅
→ SLEW每20 ms目标变化限幅
→ 标定软件限位及安全边距
→ BalancePositionControl编码器位置内环
```

编码器位置内环原有的count/STEP残差、跟随误差、无反馈、方向错误、堵转和软件限位全部保留。

## 4. 启动流程

所有正式滚球任务按以下顺序启动：

1. 检查零点、上下软件限位、位置内环故障、急停和K230链路。
2. 记录启动时最新视觉帧，只处理按键后的新帧。
3. 丢弃第1帧新的真实测量，隔离摄像头流水线旧图像。
4. 连续确认3帧`valid=1 && measured=1`、位置满足任务要求且`|v|`不超过启动速度门限。
5. 确认期间允许低权限弱控制：不使用`pred`、不使用积分，采用较小MAX和SLEW，车辆保持停止。
6. 确认完成后进入完整串级控制；Task3～Task5中涉及底盘的任务此时才启动循迹。

Task6使用三帧真实位置的中值锁定任意目标，同时要求三帧位置散布和真实速度均满足门限；锁定后目标不再漂移。

## 5. Task2（题目第3问）

状态只保留：

```text
START_VERIFY → +50 → -50 → DONE
```

不增加制动或换向语义状态。动态制动完全由串级控制器内部连续计算。

- `+50 mm`阶段：真实`pos`进入±10 mm且真实`|v|`低于正端到达速度门限，连续3帧后才把目标改为`-50 mm`。
- `-50 mm`阶段：真实`pos`进入±10 mm且真实`|v|`低于最终稳定速度门限，连续5帧后完成计时。
- 高速穿过目标但速度未降下来不能算到达。
- 完成后继续保持`-50 mm`闭环，等待人工停止。

## 6. 参数与默认起点

运行时参数：

```text
KP    位置环KPOS
KD    速度环KVEL
VMAX  最大目标钢球速度，mm/s
BIAS  水平中性偏置，encoder count
AP    正向制动加速度估计，mm/s²
AN    负向制动加速度估计，mm/s²
TD    端到端延迟补偿，ms
BM    额外制动余量，mm
VAPP  接近目标时的速度限幅，mm/s
DIR   摆杆方向符号
MAX   最大摆杆偏移，encoder count
SLEW  每20 ms最大目标count变化
DB/RG 编码器tracking死区与重新接合门限
T     手动测试目标，正式中心任务固定为0
```

编译默认值只作为安全起调值，不代表最终比赛参数：

```text
KP=1.50 KD=0.90 VMAX=90 BIAS=0
AP=500 AN=500 TD=80 BM=5 VAPP=20
DIR=-1 MAX=80 SLEW=5 DB=2 RG=3 T=0
```

最终实测参数优先固化为编译默认值，不要求比赛时依赖PC或Flash在线参数。

## 7. K230帧准入

协议保持不变：

```text
@B,seq,time,valid,state,pos,pred,v,conf,measured*CS\n
```

不检查`state`字符串语义。对于`valid=1 && measured=1`的真实帧，如果`pos`超出±150 mm或`|v|>3000 mm/s`，整帧拒绝，不能把异常速度静默改成0后送入速度环。`pred`异常可回退到`pos`，因为本轮不使用`pred`控制。

## 9. 验收顺序

1. 静止中心：`T=0`，正负两侧放球，确认均向中心运动，编码器目标跟随且无保护故障。
2. 串级语义：改变`KP`应明显改变目标运动积极程度；改变`KD`应明显改变速度制动强度；`BIAS`只修正长期单侧漂移。
3. 动态制动：从不同初速度接近同一目标，速度越大越早出现反向摆杆制动；不能依赖固定4.x cm点。
4. Task2：+50必须位置和速度连续3帧满足才折返，-50连续5帧满足才完成，总时间目标不超过5 s。
5. Task6：任意点静止启动可锁定，速度过大或三帧散布过大时不得锁定。
6. 异常：单个坏帧不突变；短时坏帧保持；持续超时进入LOST并回水平；恢复后重新确认。
7. 底盘并行：Task3～Task5滚球闭环和循迹同时更新，人工停止前不因横线或记圈逻辑自动终止。
