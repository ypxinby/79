- [x] 支持固定V3格式：


- [x] 实现XOR校验、字段数量、数字格式、长度和ASCII字符检查。

### 小球位置和速度处理

- [x] TI已经使用K230的真实位置`pos`自行计算滚球速度。
- [x] TI按实际相邻合法帧的本地接收时间计算`dt`，不假设严格50 ms。
- [x] 当前速度计算关系为：

```text
raw_velocity_mm_s = (new_pos_mm - old_pos_mm) × 1000 / delta_time_ms
```

- [x] TI再对速度进行一阶低通：

```text
velocity_used = (3 × previous_velocity + raw_velocity) / 4
```

- [x] 单次位置跳变超过60 mm时拒绝该次更新。
- [x] 无效帧不更新速度历史。
- [x] LOST后清除旧位置和速度历史，重新识别时不会拿丢失前后的坐标直接计算速度。

因此，K230组不需要为了第一版完赛重新承担“必须向TI提供可直接用于D项的高质量速度”的任务。K230仍可继续输出已有的`v`用于日志和后续对比，但TI第一版不会依赖它。

### 小球控制

## 0.3 TI对K230原联合逻辑设计的具体调整

| 原联合文档设想 | TI第一版实际决定 | 原因 |
|---|---|---|
| TI同时信任K230的`pos`和`v` | TI使用`pos`，速度由TI对合法`pos`差分计算 | TI已有实现，能够保证坏帧不参与速度计算，避免双方重复开发 |
| 使用`pred`和动态权重`W`补偿延迟 | 第一版`W=0`，不使用`pred`控制 | 静止中心尚在调参，过早加入预测会增加无法区分的变量 |
| 使用位置→目标速度→摆杆角度串级控制 | 第一版保留现有`P位置-D速度→轴count` | 两者第一阶段作用等价，现有代码和调参工具已经完成 |
| K230速度和预测属于完赛前置能力 | 改为后续优化能力 | 题3～6第一版只依赖真实位置即可开发和验收 |
| TI根据`state/conf/measured`共同判断控制 | 第一版核心判断为`seq + valid + measured + pos` | 减少字符串状态和置信度标度差异造成的永久WAIT/LOST |
| 启动后固定丢弃1～3帧 | 第一版只记录启动时seq并确认后续3帧真实测量 | 更简单，避免固定魔数和额外时间；若实测有污染再增加配置 |
| 题3～6逻辑已经完整 | 当前只是设计已确定，TI状态机仍待编码 | 必须区分文档设计完成和源码实现完成 |
| 完成后继续运行等待人工停止 | 保留该行为 | 已得到项目组确认，DONE只停止计时和锁存结果，不立即关闭控制 |

以上调整不修改V3协议字段，也不会要求K230返工已经完成的串口发送框架。

## 0.4 为什么TI暂时不用K230的速度`v`

这不是认为K230速度没有价值，而是为了第一版快速、可解释地落地：

1. TI已经拿到每一帧真实`pos`和本地接收时间，可以自行计算速度。
2. TI明确知道哪些帧通过了校验、序号、范围和跳变检查。
3. TI可以保证无效帧、HOLD和LOST前后不参与速度差分。
4. 如果同时使用K230速度和TI差分速度，出现抖动时难以判断根因。
5. 题目20～23 Hz的视觉频率下，先用一套速度来源最容易完成PD调参。

因此双方约定：

```text
第一版控制速度来源：TI_local_velocity
K230 v：继续发送，作为日志和后续对比
K230 pred：继续发送，第一版不用于控制
```

如果K230当前还没有可靠速度，可以直接发送：

```text
pred=pos
v=0
```

这不会阻塞TI开发，也不会被视为K230功能未完成。

后续只有在静止中心、题3和基础车辆运行已经通过，并且曲线证明TI速度噪声成为主要问题时，双方才联合比较：

```text
TI_local_velocity
K230 reported v
实际控制效果
```

确认K230速度更好后，TI再通过一次明确的软件版本变更切换速度源，K230组不得自行假设TI已经使用`v`。

## 0.5 为什么仍保留`pred/v/conf/state`字段

协议不删字段，原因是：

- 保持双方已经完成的V3协议兼容。
- 便于联合日志分析。
- 为后续预测和速度优化预留能力。
- 避免比赛期间再次修改协议和两端解析器。

但“协议中存在字段”不等于“TI第一版必须使用该字段”。K230组评估工作量时应按本文件中的P0/P1/P2优先级执行。

## 2. 电气连接和串口配置

```text

K230 TX  → G3507 PB3 / UART3_RX

```

注意事项：

- [ ] 两块板必须共地。
- [ ] 禁止把5 V TTL信号直接输入G3507。
- [ ] 第一阶段只要求K230单向发送，G3507 PB2/UART3_TX可以不接。

## 3. 唯一允许的帧格式

```text
@B,seq,time,valid,state,pos,pred,v,conf,measured*CS\n
```

要求：

- [ ] 整帧为ASCII文本。
- [ ] 字段严格为10项，顺序不可改变。
- [ ] 行尾允许`\n`或`\r\n`。
- [ ] 每一帧必须具有独立换行，不允许多帧粘在同一行。
- [ ] 单行总长度必须小于96字节。
- [ ] 禁止发送NaN、Inf、空字段、科学计数法、中文或其他控制字符。

## 4. XOR校验规则

校验范围是从`B`开始到`*`前一个字符为止的所有ASCII字节，不包含`@`、`*`、校验字符和换行。

```python
body = "B,100,5000,1,TRACK,20.0,20.0,0.0,0.920,1"
cs = 0
for value in body.encode("ascii"):
    cs ^= value
line = f"@{body}*{cs:02X}\n"
uart.write(line.encode("ascii"))
```

输出应为：

```text
@B,100,5000,1,TRACK,20.0,20.0,0.0,0.920,1*1E\n
```

## 5. 各字段冻结定义

| 字段 | K230输出要求 | 第一版TI用途 |
|---|---|---|
| `seq` | `uint16`，每发送一帧加1，65535后回0 | 判断新帧、重复帧、启动后的新数据 |
| `time` | K230启动后的`uint32`毫秒时间，单调递增 | 判断K230重启和日志对齐，不直接计算帧年龄 |
| `valid` | 只有当前存在可用于控制的真实钢球轨迹时为1 | 核心有效性条件 |
| `state` | 固定使用`ACQUIRE/TRACK/HOLD/LOST` | OLED和日志诊断，第一版不直接控制电机 |
| `pos` | 小球相对O点的真实一维位置，单位mm | 核心控制量、目标锁定和完成判断 |
| `pred` | 预测位置，单位mm；第一版可直接等于`pos` | 保留，第一版不参与控制 |
| `v` | 速度，单位mm/s；第一版可置0 | 保留，第一版不参与控制 |
| `conf` | 推荐固定使用`0.000～1.000`格式 | 日志和诊断，第一版不阻止控制 |
| `measured` | 本帧是否获得真实视觉测量，真实测量为1 | 与`valid`共同确认真实测量帧 |

数字允许最多3位小数。TI会将`pos/pred/v`四舍五入为整数毫米，因此推荐发送一位小数即可。


示例：

```text
@B,102,5100,0,HOLD,20.0,20.0,0.0,0.000,0*56\n
```

### 6.4 已经完全丢失目标

```text
valid=0
measured=0
state=LOST
```

示例：

```text
@B,103,5150,0,LOST,20.0,20.0,0.0,0.000,0*59\n
```

### 6.5 禁止的组合

第一版禁止发送：

```text
valid=1, measured=0
valid=0, measured=1
state=TRACK但valid=0
state=LOST但valid=1
```

如果以后需要让预测帧参与控制，必须由双方重新评审语义；不能由K230单方面改变。

## 7. 坐标系和物理标定

冻结定义：

```text
O点   = 0 mm
+5 cm = +50 mm
-5 cm = -50 mm
有效总长 = 300 mm
合法范围 = -150～+150 mm
```

K230组必须完成：

- [ ] 在水管上使用真实刻度标记O点。
- [ ] 明确物理哪一侧为正方向，并形成照片或示意图。
- [ ] 相机、水管和支架安装完成后再做最终标定。
- [ ] 标定参数必须保存到配置文件或代码常量，重启后不能丢失。
- [ ] 不得因为重新识别目标而改变O点。
- [ ] 不得把越界误检钳位成`±150 mm`后继续发送`valid=1`；越界或明显异常应发送无效状态。
- [ ] 真正位于端部附近的钢球仍应正常识别，不能简单删除整个边缘区域。

### 7.1 必测位置

摆杆水平时至少测量：

```text
-100 mm
-50 mm
0 mm
+50 mm
+100 mm
```

每个位置连续采集不少于100帧，并记录：

```text
平均值
最大值/最小值
平均绝对误差
标准差或峰峰值
有效帧率
```

### 7.2 倾斜造成的透视误差

同样五个位置还必须在以下姿态复测：

```text
摆杆水平
比赛允许的最大正倾角
比赛允许的最大负倾角
```

第一版建议验收目标：

- [ ] 0、±50、±100 mm位置的平均绝对误差尽量不超过5 mm。
- [ ] 静止位置短时峰峰值尽量不超过6 mm。
- [ ] 倾斜后误差不能接近或超过题目允许的10 mm。

如果倾斜后的误差明显增大，K230组需要修正映射或向TI组提交完整误差表，由TI根据当前摆杆编码器count进行补偿。第一阶段不修改通信帧格式。

## 8. 视觉识别与轨迹管理要求

具体模型和滤波算法由K230组决定，但输出必须满足：

- [ ] 只在水管有效ROI内寻找目标。
- [ ] 检查类别、置信度、框尺寸和长宽比。
- [ ] 相邻帧目标位置跳变必须符合钢球物理运动可能性。
- [ ] 多个候选框出现时，优先保持已有连续轨迹，不能随意切换目标。
- [ ] 新目标至少经过连续帧确认后才能进入`TRACK`，建议3帧。
- [ ] 单帧异常框不得直接更新`pos`为大跳变值。
- [ ] 从`LOST`重新发现钢球后重新建立位置和速度历史，不能用丢失前后两个位置直接计算速度。
- [ ] 滤波不能引入过大延迟；优先保证真实、稳定和连续，不追求视觉曲线绝对光滑。
- [ ] 相机曝光、白平衡和阈值应尽量固定，避免运行中画面参数突变。

## 9. 丢失、遮挡和重新识别

K230必须持续发送帧，即使没有识别到钢球也不能停止UART。

推荐流程：

```text
TRACK
→ 单帧或短时未检测：HOLD，valid=0，measured=0
→ 持续未检测：LOST，valid=0，measured=0
→ 重新发现候选：ACQUIRE
→ 连续确认成功：TRACK，valid=1，measured=1
```

要求：

- [ ] 遮挡期间不得把其他物体作为钢球持续输出`valid=1`。
- [ ] 恢复后的第一帧不得沿用丢失前的错误速度历史。
- [ ] 重新进入TRACK后，`seq`和`time`继续正常递增，不需要重新启动程序。
- [ ] K230不得等待TI发送RESET或题号才能恢复识别。
- [ ] 在钢球重新稳定可见后，建议3帧内恢复TRACK。

TI当前安全时间为：

```text
150 ms没有新真实位置：停止使用旧测量
400 ms没有新真实位置：进入视觉LOST处理
```

因此正常工作时不能频繁出现超过150 ms的发送或识别空档。

## 10. 发送频率、实时性和稳定性

- [ ] 正常平均发送频率保持在20～23 Hz。
- [ ] 正常帧间隔应大致稳定在43～50 ms附近。
- [ ] 禁止把多帧积压后一次性突发发送。
- [ ] 每发送一帧，无论有效或无效，`seq`都必须递增一次。
- [ ] 同一`seq`不得重复发送多次。
- [ ] 视觉处理、OLED/屏幕显示、图片保存和日志不得使UART长时间停顿。
- [ ] 正常连续运行时不应出现超过150 ms的帧间隔。
- [ ] K230程序异常重启后允许`seq/time`归零，TI会通过时间回退识别新会话。
- [ ] 需要记录实际帧率、最小/最大帧间隔、长间隔次数和重启次数。

推荐长时间验收：

```text
连续运行10分钟
无程序崩溃
无串口停止
无连续错误帧
正常可见时合法真实帧比例≥99%
```

## 11. `pred`、`v`和`conf`的阶段要求

### 11.1 第一版完赛要求

第一版TI控制只使用真实`pos`，速度由TI对合法位置差分计算。因此K230允许：

```text
pred = pos
v = 0
```

`conf`只用于日志，不作为TI控制门槛。K230组应固定置信度格式，推荐始终发送`0.000～1.000`，不要在不同版本中切换成`0～1000`。

### 11.2 后续优化要求

只有完成以下验证后，TI才会考虑使用K230的`v/pred`：

- [ ] `v`只由连续真实测量计算。
- [ ] 无效帧、HOLD帧和LOST前后的帧不参与错误差分。
- [ ] 静止球速度噪声明显小于TI整数毫米差分速度。
- [ ] `pred`使用经过标定的端到端预测时间，而不只是模型推理时间。
- [ ] 制动、换向和目标附近没有明显预测过冲。

在双方完成联合曲线对比前，K230不得要求TI必须使用`v/pred`才能正常工作。

## 12. 对题3～6的视觉支持要求

### 12.1 题3：O点到+50 mm再到-50 mm

K230只需持续准确输出真实位置：

- [ ] O点附近稳定测量。
- [ ] 正向全过程连续测量。
- [ ] +50 mm附近不过早丢失或裁剪。
- [ ] 反向全过程连续测量。
- [ ] -50 mm附近可长期稳定测量。

K230不负责切换目标和判断到达。

### 12.2 题4、5：运动中保持O点

- [ ] 小车启动振动时仍尽量保持识别。
- [ ] 直线和弯道中相机画面变化不能造成坐标原点漂移。
- [ ] 不因车身振动频繁在TRACK与LOST之间切换。
- [ ] 光照变化、背景黑线和车体结构不能被误识别为钢球。

### 12.3 题6：任意初始位置保持一圈

- [ ] 启动前任意合法位置都能正常输出毫米坐标。
- [ ] 不得自动把任意初始位置重定义为0 mm。
- [ ] 按键前后坐标原点和滤波状态保持一致。
- [ ] TI将使用启动后的3帧真实`pos`中值锁定目标；K230无需知道按键时刻。
- [ ] 靠近正负端部的位置也必须验证识别和坐标精度。

## 18. 最终冻结结论

K230组当前最重要的交付不是增加控制逻辑，而是：

```text
测得准
发得稳
状态语义一致
丢失后能恢复
装车倾斜后仍满足精度
```

只要K230能够稳定提供`seq + valid + measured + pos`，TI就能够独立实现题3～6；`pred/v/conf/state`中的扩展信息不应成为第一版完赛的前置依赖。
