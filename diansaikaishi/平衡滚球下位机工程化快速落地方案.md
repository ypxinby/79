# 平衡滚球下位机工程化快速落地方案

> 版本：V1.0（2026-07-31）  
> 目标：在电赛时间约束下，用最小可验证闭环完成“视觉测球—下位机控轴—小球稳定”的核心链路。本文以当前 `diansaikaishi` 工程源码为准；历史蓝牙、旧双轴云台和未完成任务流程不作为本方案依赖。

## 1. 先给结论

当前系统已经具备工程化骨架：K230 有线发送小球毫米坐标，G3507 接收并做合法性过滤，步进轴通过 MT6816 AB 编码器实现位置闭环，软件保存 ZERO/LOW/HIGH，外层提供小球 PD 控制入口，并具有超时、无反馈、跟随误差、方向和急停保护。

但必须明确：当前小球控制参数仍是“保守调试参数”，实机表现为“识别到小球后电机有轻微反应，但尚未稳定拉回中心”。直接原因是当前 `Kp=0.30 count/mm`，例如 10 mm 误差只产生约 3 count，小于位置内环重新动作门限 8 count；更本质的问题是连续更新的平衡 tracking 与一次性点位运动共用了 `DEADBAND=4 / REENGAGE=8`，外环的小输出被内环量化门限吞掉。因此第一优先级不是只把 Kp 改大，而是为 tracking 模式建立专用的小死区/重新动作门限，同时补齐可观测遥测。

最小落地顺序：

1. 机械、电气和编码器方向确认；
2. 手动设置 ZERO，并标定 LOW/HIGH；
3. 验证位置内环（指定位置、往返、堵转）；
4. K230 发送 20 Hz 合法帧，OLED 确认位置和接收状态；
5. 打通 50 Hz 平衡专用遥测，能够记录球位置、误差、速度、PD输出、编码器位置和状态；
6. 放球确认纠偏方向，为 tracking 使用专用小门限，并用通过筛选的有效位置差分作为 D 项速度；
7. 通过 OLED 参数页逐步整定 PD，先静止中心，再做题目要求的运动状态机。

## 2. 系统分层与职责

```text
K230固定俯视相机
  └─ 视觉识别、像素→毫米、置信度、速度/预测（20 Hz）
       ↓ UART3 / PB3 RX
MSPM0G3507 下位机
  ├─ vision_protocol / vision_receiver：帧解析、校验、丢帧和超时
  ├─ balance_ball_control：小球位置外环 PD（20 ms）
  ├─ balance_position_control：步进位置内环（编码器反馈）
  ├─ balance_encoder：MT6816 AB×4 计数、方向、测速
  ├─ balance_soft_limits / calibration_store：ZERO、LOW、HIGH 与 Flash
  ├─ gimbal_stepper：STEP/DIR/EN 脉冲输出
  └─ emergency_stop / watchdog / fault：统一停车和故障锁存
       ↓
普通步进驱动器 → 步进电机 → 水管俯仰轴 → 小球
```

K230 只负责“测量”，不直接产生步进脉冲，也不保存下位机限位状态。G3507 负责实时、安全和最终执行；视觉失联、数据异常或轴故障时由 G3507 自主回水平/停车。

## 3. 接线与资源

| 功能 | G3507 引脚 | 外部连接 |
|---|---|---|
| K230 UART TX（下位机接收） | PB3 / UART3_RX | K230 TX，3.3 V TTL |
| K230 UART RX（下位机发送） | PB2 / UART3_TX | K230 RX（可选，可用于状态返回） |
| 电脑调参串口TX | PA21 / UART2_TX | 接USB-TTL RX |
| 电脑调参串口RX | PA22 / UART2_RX | 接USB-TTL TX |
| 步进脉冲 | PB4 | 驱动器 STEP/PUL |
| 步进方向 | PA1 | 驱动器 DIR |
| 步进使能 | PA2 | 驱动器 ENA（按驱动器有效电平确认） |
| MT6816 A 相 | PB6 | 编码器 A |
| MT6816 B 相 | PB7 | 编码器 B |
| 继电器控制 | PB5 | 3.3 V 高电平触发继电器 IN |
| 地 | GND | K230、编码器、驱动器控制地共地 |

MT6816 使用 AB 模式：VCC 接 3.3 V，A/B 接 PB6/PB7，PWM、Z 当前不使用。模块标称 1024 线，AB 四倍频为 4096 count/rev。步进驱动器按当前 3200 STEP/rev 配置，理论换算为 `4096/3200=1.28 encoder count/step`。PB5 只驱动继电器输入，不能直接给 5 V/0.3 A 电磁铁供电；继电器触点侧单独供电，建议 PB5 加 10 kΩ 下拉。

蓝牙 HC-06 已停用，PB6/PB7 不再是蓝牙 UART，而是平衡轴编码器；不要同时恢复旧蓝牙初始化或旧云台引脚复用。

实时串口调参需要一条“下位机TX遥测 + 电脑TX命令”的全双工链路。不能把USB-TTL的TX和K230的TX同时接到PB3，否则两个推挽输出会产生电气冲突。当前工程已经新增独立`UART_BALANCE_TUNING`：UART2、115200、8N1、PA21 TX、PA22 RX。K230继续独占PB2/PB3。

1. **当前采用：独立调参UART。** PA21接USB-TTL RX，PA22接USB-TTL TX，双方共地。这是最终推荐接法。USB-TTL信号电平必须为3.3 V，不能向G3507输入5 V TTL。
2. **备选：K230做转发桥。** PC调参脚本连接K230，K230把ASCII调参命令与视觉帧依次发给PB3，并把PB2返回的遥测转发给PC。优点是不增加G3507引脚，缺点是需要视觉端额外开发和排查两级链路。
3. **仅做单项测试：临时拔掉K230。** USB-TTL直接接PB2/PB3，只能测试串口参数和步进轴，无法同时获得真实视觉位置，不能用于最终PD整定。

## 4. K230→G3507 通信协议

### 4.1 物理层

```text
UART：115200 baud，8 data bits，no parity，1 stop bit，无流控
频率：20 Hz（每 50 ms 一帧）
方向：K230 TX → G3507 PB3；共地
```

### 4.2 帧格式

```text
@B,seq,time,valid,state,pos,pred,v,conf,measured*CS\n
```

字段含义：

| 字段 | 含义 |
|---|---|
| `seq` | K230 启动后递增的 uint16 序号，溢出回 0 |
| `time` | K230 启动后的毫秒计时，回退视为 K230 重启 |
| `valid` | 0/1，当前识别是否有效 |
| `state` | 如 `TRACK`、`LOST`，仅字母/数字/`_`/`-` |
| `pos` | 小球相对 O 点的位置，单位 mm；O=0，右/正方向为正；真实水管总长250mm |
| `pred` | 预测位置，mm；当前控制可暂时等同 pos |
| `v` | 小球速度，mm/s |
| `conf` | 置信度，支持 0～1.000 或 0～1000；下位机统一为 0～1000 |
| `measured` | 0/1，是否为真实测量帧 |
| `CS` | 两位大写十六进制 XOR 校验 |

校验范围是 `B` 到 `*` 前的全部 ASCII 字节，不包含 `@`、`*`、CS 和换行。示例：

```text
@B,0,0,1,TRACK,20.0,21.0,5.0,0.900,1*2C\n
```

### 4.3 下位机过滤和超时

- 必须完整收到 `@B, ... *CS` 和换行；字段必须严格 10 项。
- 非 ASCII、控制字符、超长行、数值溢出、非法 state、校验错误直接丢弃。
- 真实水管长度为250mm、正常物理范围约-125～125mm；协议对`pos/pred`使用-150～150mm异常保护余量。两者不能混作同一个映射长度。`|v|≤3000 mm/s`，`valid/measured`只能为0/1。
- 重复或旧 `seq` 不更新控制量；K230 `time` 回退允许开启新会话。
- 合法帧需连续 3 帧且置信度≥200 才允许进入 ACT。
- 超过 150 ms 无新合法帧：停止使用旧位置并向水平回收；超过 400 ms：进入 `VISION_LOST`，不再追踪。

BALL/VRX 调试页中的 `X/F/R` 分别表示原始字节数、完整行数、拒绝行数。`X=0` 先查接线和 UART；`X>0,F=0` 查换行和帧头；`F>0,R>0` 查字段或校验。

## 5. 上电、校零和软件限位

MT6816 为增量式 AB 编码器，断电后计数会丢失，且轴可能被人为移动。因此 Flash 不能替代回零开关；当前最小方案是“每次上电人工把水管放到真实水平，再按键设 ZERO”。

### 5.1 ZERO 定义

ZERO 是水管物理水平位置，不是 HIGH/LOW 端点。逻辑计数在 ZERO 处归零，方向反装只需通过 `BALANCE_ENCODER_DIRECTION_SIGN` 修正，随后重新标定。

### 5.2 标定流程

1. 将水管放到水平，平衡轴页面长按 K1，保存当前原始计数为逻辑 0。
2. 进入 `CAL:LOW`，用 K2/K3 点动到一侧，长按 K1 确认。
3. 进入 `CAL:HIGH`，移动到另一侧，长按 K1 确认。
4. 程序自动对两个端点排序并写入 Flash。

合法条件：`minimum < 0 < maximum`，且跨度至少 64 count。`RANGEERR` 通常表示 ZERO 不在两个端点之间或跨度不足，不是单纯“电机反装”；反装时先修正方向或按实际方向重新标定。

普通上电只需重复第 1 步，然后恢复 Flash 中的 LOW/HIGH 偏移。若机械结构改变、端点记号改变或方向参数改变，必须重新完整标定。

## 6. 步进电机与编码器底层

### 6.1 已完成的最小能力

- 复用已验证的开环 STEP/DIR/EN 脉冲逻辑；
- AB 正交四倍频计数、方向判定、10 ms M 法测速；
- STEP 与编码器 count 换算；
- 位置内环：死区、再启动门限、限位夹紧、到位保持；
- 故障：软限位、超时、无反馈、跟随误差、方向错误；
- 故障锁存，故障后不自动重试，需人工复位。

测速公式（MT6816 1024 线 AB×4）：

```text
RPM = n × 100 × 60 / 4096
```

其中 `n` 是固定 10 ms 窗口内的 count 增量。若沿用资料中的 4000，应明确那是近似值；当前工程配置使用准确的 4096。

### 6.2 当前关键参数

```c
DEADBAND                 = 4 counts
REENGAGE                 = 8 counts
LIMIT_MARGIN             = 8 counts
STEP_RATE                = 40～200 Hz
NO_FEEDBACK_THRESHOLD    = 32 steps
FOLLOW_ERROR             = 64 counts，持续 200 ms
DIRECTION_ERROR          = 100 ms
POSITION_TIMEOUT         = 按距离估算，最小 3 s
```

位置内环每 20 ms 更新一次目标，编码器 ISR 独立维护计数。目标落入死区则停止发脉冲并保持；超出死区后按误差选择步频，接近限位自动夹紧。

### 6.3 当前底层的两个待优化点

第一，点位运动与 tracking 当前共用同一组死区。点位运动需要较大的到位稳定区，防止在目标附近来回找位；平衡 tracking 本身每 20 ms 都会更新目标，更需要响应小误差。下一版应分别配置：

```text
普通点位运动：DEADBAND=4，REENGAGE=8（先保留）
平衡 tracking：建议从 DEADBAND=2，REENGAGE=3 起步
```

实现时应由 `tracking_enabled` 选择门限，不要全局降低普通点位运动门限，否则可能破坏已经通过的限位往返测试。

第二，`count_error_to_steps()` 已加入带符号的换算残差累加器。由于 `4096 count/rev ÷ 3200 step/rev = 1.28 count/step`，本周期不足一个完整 STEP 的分数会保留到下一周期；开始新动作、取消、故障和重新校零时统一清零。残差只影响目标STEP整数换算，堵转、断线、方向与跟随误差仍按实际发出步数和编码器反馈判断。

## 7. 小球 PD 外环

目标为小球相对 O 点的毫米位置，默认 `target=0 mm`。每 20 ms 执行：

```text
error = target - pos
u = Kp × error - Kd × velocity
目标轴位置 = 当前轴逻辑位置 + u
```

当前装机默认参数（根据约±10°对应+332/-355 count、约5°起滑角重新映射）：

```c
Kp = 6.00 count/mm
Kd = 0.10 count/(mm/s)
TILT_SIGN = +1
MAX_OFFSET = min(运行时MAX, 软件限位安全余量)
MAX默认 = 200 count，约对应5.6～6.0°
TARGET_SLEW = 5 counts/20 ms
```

`MAX`现在是真实、可见的控制幅度上限，不再叠加隐藏的标定范围百分比限制；LOW/HIGH软件限位和安全余量仍是最终硬保护。实测平均约34 count/°，原`MAX=64`只允许约1.9°，且原小Kp在30～50mm误差下无法达到约5°起滑角，是摆动幅度微小的直接原因。新默认值只是一组与当前机械匹配的调参起点，仍需实机闭环验收。实机调试顺序：

1. 将球放在 `+30 mm`，观察水管是否使球向 O 移动；反向则把 `TILT_SIGN` 改为 -1。
2. 将位置内环 tracking 死区临时降到约 2 count、重新动作门限约 3 count，避免小误差被 8 count 门限吞掉。
3. 先以`Kp=6.00、Kd=0、MAX=200、SLEW=5`确认球能克服静摩擦向中心运动；如动作过猛，优先降低Kp或MAX。确认纯P有效后，从`Kd=0.05～0.10`开始增加阻尼。
4. 先只调静止中心，不加入 I 项；确认无持续振荡后再做题目 3 的往返动作。

当前D项速度由G3507对连续通过 `valid=1 && measured=1`、帧时效和位置范围检查的毫米坐标做差分，再进行一阶低通。被判定为无效、非真实测量或位置跳变的视觉帧不会更新速度历史，因此不会拿坏帧、HOLD帧和恢复后的第一帧错误差分。协议中的K230 `v`、`pred`、`conf`和`state`字段继续保留以保持接口兼容、日志和后续优化，但当前最小落地版本不让这些非控制字段阻止真实`pos`重捕获；越界`pred`回退为当前`pos`，越界`v`清零，第一版控制有效性以新序号、`valid=1`、`measured=1`且`pos`位于水管范围内为准。

视觉丢失超过400 ms进入`LOST`后不会锁死。重新收到新序号且`valid=1 && measured=1`的真实位置时，控制器清除丢失前的位置/速度历史，连续3帧真实测量后自动按`LOST → VIS → ACT`恢复；恢复不需要重新启动TASK5。这样既避免用丢失前坐标与新坐标计算错误速度，也避免K230的预测值、速度值、状态字符串或置信度标度差异导致永久LOST。

### 7.1 快速调参基础设施

仅靠 OLED 看瞬时 `E/V/U` 无法分析几百毫秒内的发散或振荡。工程已有 `debug_telemetry.c` 和 UART TX 队列骨架，但当前开关关闭、周期是 100 ms，而且原有 `$DBG` 内容主要是小车状态，不包含完整平衡变量。因此不能只打开开关。

参考 `vofa_pid_monitor.py`，推荐采用“下位机二进制JustFloat遥测 + 上位机ASCII命令”的双向串口。二进制遥测方向和ASCII命令方向相反，不会在同一接收流中互相混淆；下位机发送必须使用非阻塞环形队列，调参命令按换行分帧并设置最大长度。

参考脚本值得复用的能力：自动断线重连、按JustFloat尾部恢复帧同步、有限值和范围检查、20秒滑动曲线、CSV保存、调参操作日志与最近几秒统计。不能原样复用其16通道定义，因为原脚本使用像素、角度和PID的I项，而当前G3507方案使用毫米、编码器count和PD。

建议G3507每20 ms发送16个小端`float32`，最后追加JustFloat尾：

```text
00 00 80 7F
```

每帧固定68字节，50 Hz约3400 B/s，115200波特率余量充足。16通道定义为：

| CH | 字段 | 单位/说明 |
|---|---|---|
| 0 | `position_mm` | K230当前小球位置，mm |
| 1 | `predicted_mm` | K230预测位置，mm |
| 2 | `velocity_used_mm_s` | D项实际采用的速度 |
| 3 | `error_mm` | `target-position` |
| 4 | `p_count` | P项输出，encoder count |
| 5 | `d_count` | D项输出，encoder count |
| 6 | `pd_output_count` | 限幅前PD合成输出 |
| 7 | `commanded_offset_count` | slew和限幅后的轴偏移 |
| 8 | `encoder_count` | 平衡轴当前逻辑编码器位置 |
| 9 | `signed_step_rate_hz` | 带方向的STEP频率 |
| 10 | `vision_valid` | 0/1 |
| 11 | `vision_age_ms` | 最后一帧年龄 |
| 12 | `kp_count_per_mm` | 当前运行时Kp |
| 13 | `kd_count_per_mm_s` | 当前运行时Kd |
| 14 | `tracking_deadband_count` | tracking死区 |
| 15 | `controller_state` | 外环状态枚举转float |
固件与Python工具均保持固定16通道解析，使用JustFloat帧尾恢复同步。

上位机命令沿用简单ASCII行，但针对当前PD控制重定义：

```text
KP=1.00             # Kp，count/mm
KD=0.08             # Kd，count/(mm/s)
DIR=1               # +1或-1
MAX=128             # 最大轴偏移count
SLEW=8              # 每20ms最大目标变化count
DB=2                # tracking deadband
RG=3                # tracking reengage，必须大于DB
RUN                 # 启动中心平衡
STOP                # 无条件退出并回水平；X是STOP的短别名
GET                 # 返回全部参数；?是GET的短别名
DEF                 # 停止状态恢复编译默认值
```

当前控制器没有I项，因此参考脚本中的`BKI`和I曲线已删除，第一版不为兼容脚本引入积分控制。每条命令回复`ACK`、`ERR`或`CFG`；二进制帧和ASCII回复在TX队列中按完整消息串行发送，禁止在一个JustFloat帧中间插入ACK字节。配套工具为`tools/balance_pid_monitor.py`，同时提取固定尾二进制帧和换行ASCII回复。

参数安全规则：

- 所有数值先做格式、有限值和上下限检查，再原子更新运行参数；
- `STOP`和急停始终允许，不受当前状态限制；
- Kp/Kd允许运行时小步更新；`DIR/DB/RG/MAX/SLEW`只允许在控制停止时修改，避免在线突变导致猛动作；
- 第一阶段参数只保存在RAM，复位恢复编译默认值，防止一次错误调参永久写入Flash；
- 后续若增加`BSAVE`，只能在控制关闭且参数已通过范围检查时写Flash，并保留恢复默认值命令；
- 收到超长行、非ASCII、未知命令或非法数值直接拒绝，不能影响K230视觉接收任务。

如果暂时仍使用ASCII遥测，可先输出：

```text
$BAL,t,pos,target,error,v_src,v_local,v_k230,pd,cmd,enc,axis_target,state,fault\r\n
```

但正式曲线调参优先采用固定长度JustFloat，ASCII `$BAL`保留作人眼日志或协议初期验收，不要同时高速开启两种遥测。

Kp、Kd、倾斜方向、最大偏移、目标slew和tracking门限均改为运行时参数。串口作为快速主调参入口，OLED BALL参数页作为脱离电脑后的现场兜底；两者操作同一份运行时参数结构。参数调好后再固化默认值，Flash保存不是第一阶段必需项。

界面中的“应用PD”可在运行过程中发送KP/KD；“应用轴参数”用于DIR/MAX/SLEW/DB/RG，应先按STOP。点击任意参数框后可直接用键盘`↑/↓`微调，`Shift+↑/↓`按5倍步长快调；KP每次0.05、KD每次0.01、MAX每次8 count，其余整数参数每次1。方向键只修改输入框，仍需点击对应应用按钮才会发送，避免误操作直接改变电机。工具支持自动重连、ACK/ERR/CFG显示、20秒滑动曲线和CSV保存。点击`PARAM`会先发送`GET`读取下位机实际生效参数，再在`tools/balance_logs/`保存一份参数快照，文件同时包含可重发的串口命令和可固化到`app_features.h`的默认宏值；该功能不写MCU Flash。

开发模式任务列表新增第5项`BALL-CENTER`，作为独立静止中心平衡测试入口。完成ZERO确认并恢复LOW/HIGH后，在参数页选择`TASK=5`，长按K1返回状态页，再短按K2；程序保持车轮停止、切换到BALL页面并以`target=0 mm`启动平衡。BALL页面K3短按或长按退出并平滑回水平，K2可重新请求启动。若轴未完成校零/限位恢复则显示`AXIS`，无有效视觉时显示`VIS`，正常闭环显示`ACT`。

平衡步进页面空闲状态下，`K1长按`定义为“使用编码器位置闭环回逻辑0点”，`K3长按`仍用于重新标定，`K2长按`仍为全局急停。首次完整标定在HIGH端保存完成后，再长按K1退出`CAL:DONE`时会自动启动回0，不再停在HIGH；回零过程中OLED显示`POSCTRL`且目标`T:0`，K1或K3长按可取消。该操作只回到已经确认的逻辑ZERO，不会重新设置ZERO，也不会修改Flash中的LOW/HIGH。

### 7.2 推荐的实机整定顺序

1. `Kd=0`，球分别放在 ±30 mm，确认倾斜方向正确；反向只修改 `TILT_SIGN`。
2. 启用 tracking 专用 `2/3 count` 门限，观察很小的位置目标是否真正产生STEP。
3. 逐步增加 Kp，使球能够明显回中心但不连续越过两侧。
4. 保持使用有效位置差分速度，从小到大增加 Kd 抑制过冲。
5. 最后增加最大偏移和slew；若出现撞限位，先限制输出，不加 I 项。
6. 保存一组静止中心参数，再开始车辆运动前馈，不能同时调PD和前馈。

## 8. 当前状态机与按键

| 状态 | 含义 |
|---|---|
| `OFF` | 平衡关闭，轴可回水平 |
| `WAIT_AXIS` | ZERO/限位/轴状态未就绪 |
| `WAIT_VISION` | 等待连续有效视觉帧 |
| `ACTIVE` | PD 外环驱动位置内环 |
| `RETURN_ZERO` | 退出控制，受控回水平 |
| `VISION_LOST` | 视觉超时，回水平并等待恢复 |
| `FAULT` | 轴故障锁存，停止输出 |

BALL 页面：K2 短按请求启动 O 点平衡；K3 短按退出并回水平；K2 长按急停。急停、watchdog 或轴故障均会停止步进并关闭电磁铁（如已启用）。

## 9. 故障应对策略

| 故障 | 下位机动作 | 上位机处理 |
|---|---|---|
| 帧校验/字段错误 | 丢弃，不更新位置 | 修正格式，保持周期发送 |
| 150 ms 无新帧 | 回水平 | 继续发送或进入安全停机 |
| 400 ms 视觉丢失 | `VISION_LOST`，停止追球 | 重新建立连续有效帧 |
| 软限位 | 目标夹紧；越界持续则锁故障 | 停止任务，提示人工检查 |
| 无反馈/跟随误差/方向错误 | 停止脉冲、锁存 FAULT | 发送复位前先确认机械和接线 |
| K2 长按/看门狗 | 立即停轴，关闭磁铁 | 重新上电或人工复位 |

安全原则：视觉不能替代下位机保护；上位机只能请求目标，最终限位、超时和急停必须由 G3507 独立执行。

当前“回水平”的可信度完全依赖人工设置的 ZERO。最低成本增强不是立刻改变回零方案，而是在完整标定后计算 ZERO 到两侧端点的距离比例；偏差明显时 OLED 给出 `ZERO WARN`，但只报警、不直接判定标定失败，因为实际机械行程可能本来就不对称。若后续允许增加硬件，优先增加独立水平光电/霍尔开关，实现上电自动找零；普通增量式AB编码器和Flash本身不能确认断电后的绝对水平位置。

## 11. 快速验收流程

### A. 不带球、无视觉

1. 检查 PB4/PA1/PA2 电平和驱动器使能；
2. 手动设 ZERO，标定 LOW/HIGH；
3. 指定 ±200 STEP，确认编码器计数方向、误差和回零误差；
4. 连续正反运动，确认无乱跳、无丢计数；
5. 人为阻挡轴，确认 NO_FEEDBACK/FOLLOW_ERROR 能锁故障；
6. 越过软件限位，确认不继续发脉冲。

### B. 通信

1. K230 以 20 Hz 发送固定合法示例帧；
2. OLED/VRX 确认 `X` 增加、`F` 增加、`R=0`；
3. 改变 `pos=-30/0/+30`，确认显示正负和 `valid/conf`；
4. 停止发送，确认 150/400 ms 超时状态。

### C. 串口调参和遥测

1. K230保持20 Hz视觉发送，同时启动调参COM口，确认不存在TX并接；
2. Python显示每秒约50个JustFloat有效帧、坏帧持续为0或极少；
3. 发送`GET`，确认固件返回参数与JustFloat CH12～14一致；
4. 控制关闭时依次修改`DIR/MAX/SLEW/DB/RG`，逐条收到ACK；
5. 控制运行时尝试修改方向或门限，应收到ERR；Kp/Kd小步更新应成功；
6. 拔掉USB-TTL再插回，Python自动重连且不导致下位机失控；
7. 保存CSV，确认时间、位置、P/D、轴目标、编码器和状态列完整。

### D. 静止平衡

1. 水平 ZERO 有效、LOW/HIGH 有效；
2. BALL 页面 K2 启动；
3. 球放在 O 附近，先观察轴动作方向；
4. 电脑记录 `$BAL` 遥测曲线，逐步调 Kp/Kd，记录最大误差、振荡、限幅和故障；
5. 目标是静止时误差绝对值≤1 cm，再进入题目 3～6。
