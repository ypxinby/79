# K230滚球一维视觉通信协议 V1

> 状态：冻结，可用于K230与MSPM0G3507并行开发  
> 日期：2026-07-31  
> 发送端：K230视觉程序  
> 接收端：MSPM0G3507下位机  
> 对应下位机实现：`vision_protocol.c/.h`、`vision_receiver.c/.h`

## 1. 冻结结论

第一版采用固定40字节二进制帧，并冻结为“一维滚球配置”。K230只输出小球沿水管轴线的一维当前位置，不发送二维控制坐标、电机控制量，也不需要每帧发送目标位置。

```text
K230负责：检测小球、投影到水管轴线并发送一维位置、置信度和有效标志
MSPM0负责：坐标标定、任务目标生成、PD控制、前馈、软件限位和故障保护
```

滚球控制统一使用：

```text
位置误差 = 任务目标位置 - 小球当前位置
```

任务目标由MSPM0状态机决定：

| 比赛任务 | MSPM0目标位置 |
| --- | --- |
| 题3第一阶段 | `+5 cm` |
| 题3第二阶段 | `-5 cm` |
| 题4 | 中心点`O = 0 cm` |
| 题5 | 中心点`O = 0 cm` |
| 题6 | 按键启动时对小球初始位置多帧平均并锁存 |

因此K230无须理解当前执行的是题3、题4、题5还是题6。

## 2. 接线与串口参数

### 2.1 接线

```text
K230 TX  → MSPM0 PB3（UART_VISION RX）
K230 RX  ← MSPM0 PB2（UART_VISION TX，V1暂不要求使用）
K230 GND ↔ MSPM0 GND
```

双方必须使用3.3 V TTL电平并共地。不要把RS-232电平直接接入MSPM0。

### 2.2 串口配置

```text
波特率：115200 baud
数据位：8
校验位：None
停止位：1
流控：None
字节序：小端
格式：二进制，不是字符串或JSON
```

### 2.3 发送频率

```text
推荐：50 Hz，每20 ms一帧
可接受：25～50 Hz
```

检测不到小球时也必须按相同频率发送合法的“无目标帧”，不能停止发送。这样MSPM0可以区分“视觉正常但没看到球”和“串口已经断联”。

## 3. 帧总体结构

完整帧固定为40字节：

```text
┌────────────── 8 bytes ──────────────┐
│ 帧头、版本、类型、flags、长度       │
├───────────── 30 bytes ──────────────┤
│ session、sequence、坐标、置信度等   │
├────────────── 2 bytes ──────────────┤
│ CRC-16/CCITT-FALSE                  │
└─────────────────────────────────────┘
```

固定常量：

```text
magic             = A5 5A
version           = 01
message_type      = 01（TARGET_REPORT）
reserved          = 00
payload_length    = 30 = 0x001E
frame_length      = 40
```

## 4. 逐字节字段定义

所有多字节整数均为小端序。

| Offset | 长度 | 类型 | 字段 | K230填写规则 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | `uint8` | `magic_0` | 固定`0xA5` |
| 1 | 1 | `uint8` | `magic_1` | 固定`0x5A` |
| 2 | 1 | `uint8` | `version` | 固定`0x01` |
| 3 | 1 | `uint8` | `message_type` | 固定`0x01` |
| 4 | 1 | `uint8` | `flags` | 见第5节 |
| 5 | 1 | `uint8` | `reserved` | 固定`0x00` |
| 6 | 2 | `uint16` | `payload_length` | 固定`30` |
| 8 | 4 | `uint32` | `session_id` | 每次K230视觉程序启动生成新的非零值 |
| 12 | 2 | `uint16` | `sequence` | 每发送一帧加1，允许`65535→0`回绕 |
| 14 | 4 | `uint32` | `timestamp_ms` | K230视觉程序启动后的本地毫秒数 |
| 18 | 2 | `uint16` | `frame_width` | 一维轴坐标总跨度，范围`1～8192` |
| 20 | 2 | `uint16` | `frame_height` | 一维配置固定为`1` |
| 22 | 2 | `uint16` | `target_center_x` | 小球沿水管轴线的一维位置；无目标时`0xFFFF` |
| 24 | 2 | `uint16` | `target_center_y` | 兼容占位；有效目标固定`0`，无目标固定`0xFFFF` |
| 26 | 2 | `uint16` | `confidence` | `0～1000`；无目标时`0` |
| 28 | 2 | `uint16` | `target_id` | V1滚球不用ID，固定`0xFFFF` |
| 30 | 2 | `uint16` | `bbox_x` | V1滚球不用bbox，固定`0` |
| 32 | 2 | `uint16` | `bbox_y` | V1滚球不用bbox，固定`0` |
| 34 | 2 | `uint16` | `bbox_width` | V1滚球不用bbox，固定`0` |
| 36 | 2 | `uint16` | `bbox_height` | V1滚球不用bbox，固定`0` |
| 38 | 2 | `uint16` | `crc16` | 对offset 0～37计算，结果小端存放 |

## 5. flags定义

| Bit | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `TARGET_VALID` | 当前检测到有效小球 |
| 1 | `HAS_BBOX` | V1滚球固定为0 |
| 2 | `HAS_TARGET_ID` | V1滚球固定为0 |
| 3 | `HAS_CONFIDENCE` | 有效帧携带置信度 |
| 4 | `SOURCE_RESTART` | K230视觉程序刚启动 |
| 5～7 | Reserved | 必须为0 |

正常运行推荐值：

```text
检测到小球：flags = 0x09
没有检测到：flags = 0x00
启动后前3帧检测到小球：flags = 0x19
启动后前3帧没有目标：flags = 0x10
```

`SOURCE_RESTART`只在每次视觉程序启动后的前3帧置1，之后清零。

## 6. 坐标定义

本协议只定义一个有效控制坐标：小球沿水管轴线的位置。

```text
水管负方向端：一维坐标较小
水管正方向端：一维坐标较大
单位：pixel或等价的整数轴坐标
```

K230先得到图像中的小球中心，然后将其投影到水管轴线：

```text
axis_position = dot(ball_center - axis_start, axis_unit_vector)
```

如果摄像头固定且水管始终近似水平，可以直接使用图像X坐标；如果水管在图像中倾斜，应使用上述轴线投影，避免球上下跳动被误认为沿水管移动。

帧内填写规则：

```text
frame_width      = 一维坐标总跨度，必须大于axis_position
frame_height     = 1
target_center_x  = axis_position
target_center_y  = 0
```

`target_center_y`只是为了兼容当前已经验证的通用40字节接收器，不是第二个有效坐标。MSPM0滚球控制只读取`target_center_x`。

K230不要直接计算STEP、DIR、水管角度或PID输出。

## 7. 有效小球帧

有效帧必须满足：

```text
flags = 0x09（启动前3帧为0x19）
frame_height = 1
target_center_x < frame_width
target_center_y = 0
confidence = 0～1000
target_id = 0xFFFF
bbox_x/y/width/height = 0
```

示例字段：

```text
session_id = 0x12345678
sequence = 0
timestamp_ms = 1000
frame_width = 640
frame_height = 1
target_center_x = 360
target_center_y = 0
confidence = 900
flags = 0x09
```

对应完整40字节帧：

```text
A5 5A 01 01 09 00 1E 00
78 56 34 12 00 00 E8 03 00 00
80 02 01 00 68 01 00 00
84 03 FF FF 00 00 00 00 00 00 00 00
90 99
```

该帧CRC为`0x9990`，帧尾按小端发送为`90 99`。

## 8. 无目标帧

没有检测到小球时不能沿用上一帧坐标，必须发送：

```text
flags = 0x00（启动前3帧为0x10）
target_center_x = 0xFFFF
target_center_y = 0xFFFF
confidence = 0
target_id = 0xFFFF
bbox_x/y/width/height = 0
```

示例字段：

```text
session_id = 0x12345678
sequence = 1
timestamp_ms = 1020
frame_width = 640
frame_height = 1
```

对应完整40字节帧：

```text
A5 5A 01 01 00 00 1E 00
78 56 34 12 01 00 FC 03 00 00
80 02 01 00 FF FF FF FF
00 00 FF FF 00 00 00 00 00 00 00 00
8D FD
```

该帧CRC为`0xFD8D`，帧尾为`8D FD`。

## 9. session、sequence与时间戳

### 9.1 session_id

K230视觉程序每次启动时生成一个新的非零`uint32`：

```python
session_id = random.getrandbits(32)
if session_id == 0:
    session_id = 1
```

同一次程序运行期间保持不变。MSPM0发现`session_id`变化时，会把当前帧视为视觉端新会话并重新建立序号基线。

### 9.2 sequence

```python
sequence = (sequence + 1) & 0xFFFF
```

有效帧和无目标帧都必须递增。禁止因为没有检测到小球而停止序号。

MSPM0会丢弃相同session下的重复帧和乱序旧帧，并正确接受`65535→0`回绕。

### 9.3 timestamp_ms

时间戳使用K230视觉程序启动后的单调毫秒数，只用于日志和帧间隔分析。MSPM0通信超时使用自己的本地接收时间，不要求K230和MSPM0时钟同步。

## 10. CRC算法

```text
名称：CRC-16/CCITT-FALSE
poly：0x1021
init：0xFFFF
refin：false
refout：false
xorout：0x0000
计算范围：帧offset 0～37，共38字节
存储方式：小端，低字节在前
```

Python参考：

```python
def crc16_ccitt_false(data: bytes) -> int:
    crc = 0xFFFF
    for byte in data:
        crc ^= byte << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc
```

CRC错误帧会被MSPM0直接丢弃，不更新当前小球位置，也不刷新通信有效时间。

## 11. K230打包参考代码

以下代码只依赖Python/CanMV常见的`struct`模块。UART初始化方式由K230具体固件决定。

```python
import struct

MAGIC = b"\xA5\x5A"
VERSION = 1
TYPE_TARGET_REPORT = 1
PAYLOAD_LENGTH = 30

FLAG_TARGET_VALID = 1 << 0
FLAG_HAS_CONFIDENCE = 1 << 3
FLAG_SOURCE_RESTART = 1 << 4

HEADER = struct.Struct("<2sBBBBH")
PAYLOAD = struct.Struct("<IHIHHHHHHHHHH")


def crc16_ccitt_false(data):
    crc = 0xFFFF
    for byte in data:
        crc ^= byte << 8
        for _ in range(8):
            if crc & 0x8000:
                crc = ((crc << 1) ^ 0x1021) & 0xFFFF
            else:
                crc = (crc << 1) & 0xFFFF
    return crc


def build_ball_frame(session_id, sequence, timestamp_ms,
                     axis_span_px, axis_position_px,
                     confidence, valid, source_restart=False):
    if valid:
        flags = FLAG_TARGET_VALID | FLAG_HAS_CONFIDENCE
        center_x = int(axis_position_px)
        center_y = 0
        confidence = max(0, min(1000, int(confidence)))
    else:
        flags = 0
        center_x = 0xFFFF
        center_y = 0xFFFF
        confidence = 0

    if source_restart:
        flags |= FLAG_SOURCE_RESTART

    header = HEADER.pack(
        MAGIC,
        VERSION,
        TYPE_TARGET_REPORT,
        flags,
        0,                   # reserved
        PAYLOAD_LENGTH,
    )

    payload = PAYLOAD.pack(
        session_id & 0xFFFFFFFF,
        sequence & 0xFFFF,
        timestamp_ms & 0xFFFFFFFF,
        int(axis_span_px),
        1,                    # one-dimensional profile
        center_x,
        center_y,
        confidence,
        0xFFFF,              # target_id unused
        0, 0, 0, 0,         # bbox unused
    )

    body = header + payload
    crc = crc16_ccitt_false(body)
    frame = body + struct.pack("<H", crc)
    assert len(frame) == 40
    return frame
```

发送循环示意：

```python
sequence = 0
restart_frames = 3

while True:
    # detection由K230视觉程序提供
    # valid, ball_center, confidence = detect_ball(...)
    # axis_position_px = project_to_pipe_axis(ball_center)

    frame = build_ball_frame(
        session_id=session_id,
        sequence=sequence,
        timestamp_ms=timestamp_ms,
        axis_span_px=axis_span_px,
        axis_position_px=axis_position_px,
        confidence=confidence,
        valid=valid,
        source_restart=(restart_frames > 0),
    )
    uart.write(frame)

    sequence = (sequence + 1) & 0xFFFF
    if restart_frames > 0:
        restart_frames -= 1

    # 保持约20 ms周期，即50 Hz
```

## 12. 像素与物理位置的责任边界

K230只发送当前小球沿水管轴线的一维坐标。MSPM0保存标定参数：

```text
origin_px：摆杆中心点O对应的像素
pixels_per_cm：每厘米对应的像素数
axis_sign：摄像头方向，取+1或-1
```

下位机换算：

```text
ball_position_cm =
    axis_sign × (ball_axis_px - origin_px) / pixels_per_cm
```

例如：

```text
origin_px = 320
pixels_per_cm = 8

O点目标    = 320 px
+5 cm目标  = 360 px
-5 cm目标  = 280 px
允许±1 cm = ±8 px
```

如果后续发现透视导致不同位置的比例明显不同，可以在MSPM0或K230增加分段标定，但不得修改V1帧字段语义。

## 13. 下位机计划中的失联处理

以下行为由MSPM0实现，K230只需持续正确发帧：

```text
连续3帧有效小球：允许进入小球PD控制

超过100 ms没有新的合法帧，或持续无目标：
    停止使用旧坐标
    PD输出退出
    摆杆目标平滑返回水平安全位置

超过300 ms没有合法协议帧：
    进入VISION_LOST
    保持安全位置
    不自动沿用失联前目标数据

重新连续收到3帧有效小球：
    重新建立控制输入
```

## 14. 联调验收流程

### 14.1 离线协议自检

工程已有PC测试脚本：

```powershell
python .\diansaikaishi\tools\vision_protocol_sender.py --mode self-test

# 生成/发送一维有效球坐标；有串口时追加 --port COMx
python .\diansaikaishi\tools\vision_protocol_sender.py --mode ball-1d --width 640 --x 360 --confidence 900 --fps 50 --count 100

# 连续发送一维无目标帧
python .\diansaikaishi\tools\vision_protocol_sender.py --mode ball-no-target --width 640 --fps 50 --count 100
```

必须输出：

```text
SELF-TEST PASS
header_size=8 payload_size=30 frame_size=40
```

### 14.2 串口只收不控

1. K230以50 Hz发送有效帧。
2. MSPM0 OLED显示`VALID、X、Y、confidence、sequence、FPS`。
3. 左右移动小球，确认坐标方向和数值连续。
4. 遮挡小球，确认K230继续发送无目标帧。
5. 恢复小球，确认序号继续递增。
6. 重启K230程序，确认`session_id`改变。

### 14.3 坐标标定

1. 小球放在中心O，记录`origin_px`。
2. 小球放在物理`+5 cm`记号，记录像素。
3. 小球放在物理`-5 cm`记号，记录像素。
4. 计算两侧`pixels_per_cm`并检查是否接近。
5. 确认正负方向与题目物理标记一致。

### 14.4 异常验收

必须覆盖：

```text
拔掉K230 TX
停止发送但保持供电
持续发送无目标帧
发送错误CRC
发送重复sequence
发送乱序旧sequence
K230程序重启并更换session_id
```

任何异常都不得让MSPM0继续无限使用最后一次小球坐标。

## 15. 版本冻结规则

V1冻结以下内容：

```text
帧头A5 5A
固定40字节
字段偏移和类型
小端序
CRC算法
flags语义
坐标原点和方向
无目标字段取值
```

禁止在不升级版本的情况下：

```text
把像素坐标改成厘米或毫米
把二进制改成ASCII/JSON
改变字段顺序
改变CRC计算范围
复用bbox字段传控制量
让K230直接发送STEP/DIR/PID输出
```

如果以后需要MSPM0向K230发送状态、任务号或故障码，应新增独立的消息类型，不修改当前`TARGET_REPORT = 0x01`。
